## 04 / ENGINEERING MODEL

```text
                         PRODUCT
                            │
                            ▼
                   ┌─────────────────┐
                   │  NEXT.JS / UI   │
                   └────────┬────────┘
                            │
                        HTTPS / JSON
                            │
                            ▼
               ┌─────────────────────────┐
               │    ASP.NET CORE API     │
               │                         │
               │  Auth · Validation      │
               │  Business Rules         │
               │  DTOs · Error Handling  │
               └────────────┬────────────┘
                            │
                            ▼
                     ┌─────────────┐
                     │   EF CORE   │
                     └──────┬──────┘
                            │
                            ▼
                     ┌─────────────┐
                     │ POSTGRESQL  │
                     └─────────────┘
```

| PRINCIPLE | HOW I APPROACH IT |
|---|---|
| **Boundaries** | Separate UI, API, domain behaviour and persistence responsibilities. |
| **Security** | Never trust client-controlled identity, permissions or payment state. |
| **Contracts** | Prefer explicit request/response DTOs over leaking database models. |
| **Failure** | Design validation, errors, logs and recovery paths as part of the system. |
| **Testing** | Use unit, integration and API-level tests around important behaviour. |
| **Operations** | Treat configuration, deployment and observability as engineering work. |
